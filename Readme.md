2. Evaluation Methodology & Scoring Mechanics
The agent measures controls across two distinct pillars using a weighted scoring model:A. Design Effectiveness ($DE$)Determines whether control parameters meet required regulatory baselines. The agent checks:Completeness: Are all asset classes and network zones covered?Enforcement Precision: Are rules strict enough (e.g., password entropy, session timeouts, MFA enforcement)?Frequency: Is the control scheduled at compliant intervals?B. Operating Effectiveness ($OE$)Determines operational reliability through empirical telemetry analysis over an audit sample window (e.g., 90 days). The agent calculates:Log Coverage Ratio ($C_{log}$): Percentage of systems actively reporting log data.Failure Exception Rate ($R_{fail}$): Percentage of sample events failing the control check.Mean Time to Remediate ($MTTR$): Speed of handling non-compliant events.Quantitative Scoring Model$$\text{Control Effectiveness Score (CES)} = (w_{DE} \cdot DE) + (w_{OE} \cdot OE) - P_{critical}$$Where:$w_{DE} = 0.40$ (Design Weight)$w_{OE} = 0.60$ (Operating Weight)$P_{critical}$ is an automated penalty modifier triggered by unmanaged elevated privileges or unpatched critical vulnerabilities ($CVE \ge 9.0$) past SLA.

Security, Governance & Anti-Hallucination GuardrailsBecause banking environments require strict compliance and data protection, the AI agent must operate under four core constraints:Deterministic Ground-Truth Binding:The agent never "guesses" control status. All operating effectiveness claims must explicitly cite raw log line IDs, Splunk query results, or API response payloads.Bank-Grade Data Privacy & Zero Retention:Deployed within a dedicated Virtual Private Cloud (VPC) or tenant space. Prompts and telemetry data must never be stored, cached, or used for model training.Least Privilege Read-Only Access:The agent operates using scoped, read-only API keys or service accounts without write permissions to banking core systems.Human-in-the-Loop (HITL) Validation:Critical control failure classifications, risk downgrades, or formal audit submissions require mandatory sign-off from an Information Security Officer (ISO) or internal auditor.
